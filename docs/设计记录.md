# 设计记录

## 在数据库中保存小文件

每个版本受 256 KiB 上限限制，字节与元数据在 MySQL 的同一事务内写入，可以避免对象存储与数据库双写产生的孤儿文件和悬空引用。代价是数据库存储增长及备份压力；超过当前使用规模后应评估对象存储并重新设计一致性和清理机制。

创建库和版本提交事务使用 READ COMMITTED；每次修改先锁用户行，再锁库行。这样配额和版本分配在同一用户内串行；代价是同一用户的不同库不能并行写入。版本行只追加，恢复指向来源并创建新行；幂等记录与版本写入同事务。

## 客户端替换边界

客户端在目标目录创建临时文件、校验下载，创建并校验备份，再次核对目标，记录操作日志后 `os.replace`。这不是跨文件事务：外部程序仍可在最后一次核对与替换之间写入，断电安全也取决于操作系统和文件系统。应用期间应关闭游戏和其他编辑器。状态记录能在下次运行时根据目标哈希识别替换是否完成；发现第三种内容时停止并保留证据。

无可靠判断编码时不解码、不重编码；明确指定 GB18030。差异功能的 LCS 计算受行数乘积上限限制，超出时请下载本地比较。

## 删除配置库

删除前显式确认当前 head，并以用户行、库行顺序加锁；head 不匹配时拒绝。版本、幂等记录和审计记录在同一事务删除，删除不可恢复，不影响客户端本地文件。
